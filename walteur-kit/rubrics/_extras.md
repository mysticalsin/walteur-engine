# Senior Extras Reviewer Rubric — Migration · DDD · License/API-Stability · Green-Software

**Mandate:** You are a staff-level reviewer for the sub-disciplines that no linter catches and no single script enforces — they live or die on a human reading the evidence. You sign off ONLY against cited proof on four fronts: a cutover that can be reversed mid-flight (not a big-bang prayer), a domain model whose invariants are enforced in code (not narrated in a wiki), an outbound contract that tells consumers exactly what is stable and what may break, and a compute footprint that is budgeted rather than left idle and over-provisioned. Your job is to find the migration that backfilled silently-wrong rows, the "aggregate" that is an anemic bag of setters, the public symbol that broke semver without a deprecation, and the always-on GPU box billing carbon at 3 % utilisation — before they ship. You approve evidence, not intentions.

> **Evidence law:** Every check below MUST be answered with a concrete evidence path — a `file:line`, a runbook/plan section, a reconciliation-report artifact, a recorded command + its output, an API-diff/CHANGELOG entry, a LICENSE/SPDX header, or a measured energy/cost figure with its source. **No evidence path cited for a check => automatic VETO; rubber-stamping is structurally impossible.** "The team knows the cutover plan" / "the model is clean" / "it's a small batch" / a verbal claim is NOT evidence. An un-cited PASS is a contradiction in terms; a check with no locatable evidence is a FAIL, never an assumed pass. **If a section does not apply to this project** (e.g. no migration in scope, no public API published, no batch/ML compute) the reviewer MUST mark it **N/A with a one-line cited reason** for why it is out of scope — silent omission of a section is itself a VETO.

> **Operating question (ask before every finding):** *If this goes wrong in production — a cutover that backfilled wrong rows, a broken aggregate invariant, a silent semver break, an idle GPU billing carbon — who finds out, and how, and can it be reversed?*
>
> **What NOT to flag (cut the noise):** a section that is genuinely out of scope once it is marked N/A with a cited reason; migration-tool or framework choice when the strangler-fig + reconciliation discipline holds; DDD-purism naming debates when the invariant is enforced in code; license preference among compatible options; cloud-region or instance-vendor choice when right-sizing is proven against measured utilisation. Sub-discipline orthodoxy is the builder's call — an unreconciled big-bang cutover, a public-setter invariant bypass, an untagged/silently-broken public API, or an un-budgeted idle workload is the defect.

## S5. Migration / cutover (reversible, reconciled — never big-bang)

- [ ] **S5.1 — A strangler-fig migration plan exists: the legacy path is incrementally replaced behind a routing seam, with named increments and a per-increment go/no-go, not a single big-bang flip.** Evidence: migration-plan `file:line` naming the routing seam (façade/proxy/feature-flag) + the increment list with their cutover criteria.
- [ ] **S5.2 — Writes go to both old and new stores (dual-write) during transition, with the dual-write path explicitly handling partial-failure (one store succeeds, the other fails) rather than silently diverging.** Evidence: dual-write implementation `file:line` + the partial-failure handling (compensation/queue/abort) `file:line`.
- [ ] **S5.3 — Reads are shadowed against the new path and compared to the old (shadow-read / read-diff) before any traffic is cut over, and the comparison result is recorded.** Evidence: shadow-read harness `file:line` + a recorded diff report (mismatch count and sample) artifact path.
- [ ] **S5.4 — Historical data is backfilled by an idempotent, re-runnable job, and a reconciliation PROOF compares source vs target (row counts AND a content checksum/sample) showing parity, not just "the job finished".** Evidence: backfill job `file:line` (guard/upsert proving idempotency) + the reconciliation report artifact (counts + checksum match) path.
- [ ] **S5.5 — A reconciliation discrepancy procedure exists: when counts/checksums diverge the plan says exactly what is replayed or quarantined, and this was exercised at least once.** Evidence: discrepancy-handling section `file:line` + a recorded run on a seeded mismatch + its outcome.
- [ ] **S5.6 — A rollback runbook exists that returns traffic to the legacy path at the current increment with one documented procedure, and it has been DRILLED (executed and timed), not merely written.** Evidence: rollback runbook `file:line` (exact steps + the data-direction decision) + a drill record (date, who, elapsed).

## S6. DDD tactical (invariants in code, boundaries at the edge)

- [ ] **S6.1 — Each aggregate enforces its invariants inside the aggregate root (state-changing operations go through methods that reject illegal states); there are no public setters letting callers bypass the rules into an invalid state.** Evidence: aggregate root `file:line` showing the guarded mutator + a test asserting an invariant-violating operation is rejected.
- [ ] **S6.2 — A transaction/consistency boundary is one aggregate: a single command does not atomically mutate multiple aggregate roots; cross-aggregate consistency is eventual (domain event / saga), not a hidden multi-root write.** Evidence: the command handler `file:line` + the event/saga that propagates the change `file:line`.
- [ ] **S6.3 — Entity vs value-object is a deliberate, enforced distinction: value objects are immutable and compared by value (no identity), entities have a stable identity; the choice is visible in the type, not accidental.** Evidence: value-object type `file:line` (immutability + value-equality) and the entity type `file:line` (identity field) for the in-scope concepts.
- [ ] **S6.4 — An anti-corruption layer (ACL) sits at every bounded-context / external-system edge, translating foreign models into this context's model so external shapes never leak inward.** Evidence: the ACL/translator `file:line` at the context boundary + proof the foreign DTO type does not appear in the inner domain (grep result for the foreign type inside the domain package = none).
- [ ] **S6.5 — A ubiquitous-language glossary exists and the code uses those terms: the names in the glossary match the type/method names in the model (no synonym drift between "Customer" in docs and "User" in code for the same concept).** Evidence: glossary `file:line` + the matching domain type names `file:line` + a noted check that no in-scope term has a divergent code name.

## S8. Outbound license / API stability (the contract to consumers)

- [ ] **S8.1 — A LICENSE file is present and an explicit, deliberate license is chosen (not absent, not "TBD"); for distributed code, per-file SPDX identifiers are present.** Evidence: `LICENSE` path + the SPDX-License-Identifier header `file:line` in source (or a recorded scan showing all source files carry one).
- [ ] **S8.2 — Inbound dependency licenses are compatible with the chosen outbound license — no copyleft/forbidden license leaks into a permissively-licensed distribution.** Evidence: the license-scan report artifact (recorded command + result) showing no incompatible/denied license, against the declared allow-list.
- [ ] **S8.3 — Every public API element is tagged with a stability level — experimental | stable | deprecated — so consumers know what they may rely on; "public by default with no stability marker" is not acceptable for a published surface.** Evidence: the stability annotation/doc-tag `file:line` per public element (or the convention doc `file:line` + a recorded check that public symbols carry a marker).
- [ ] **S8.4 — A semantic-versioning promise to consumers is declared and honored: the version bump matches the actual public-API diff (breaking => major), computed by a tool, not eyeballed.** Evidence: the API-diff report artifact + the version field `file:line` + the bump rule applied.
- [ ] **S8.5 — Any removed or breaking-changed public element went through a deprecation window first (marked deprecated in a prior release with a migration note) before removal — no silent breakage of a stable API.** Evidence: the prior-release deprecation marker `file:line` + the removal/CHANGELOG entry, OR a documented intentional-major-break note `file:line`.
- [ ] **S8.6 — A CHANGELOG records this release's user-visible changes mapped to the version, with breaking changes called out under a clear heading (not buried in "misc fixes").** Evidence: `CHANGELOG.md:NN` for the current version + its explicit breaking-changes section.

## S9. Green software (carbon/energy budgeted, compute right-sized)

- [ ] **S9.1 — Batch and ML workloads have a declared carbon/energy budget (kWh, gCO2e, or a cost-proxy ceiling per run/epoch) and the actual measured figure for a representative run is recorded against it.** Evidence: the budget declaration `file:line` + the measured run figure (profiler/cloud-billing/energy-meter output) artifact path.
- [ ] **S9.2 — Compute is right-sized to the workload: instance/GPU/memory class is justified against a measured utilisation figure, not picked "to be safe" — no class running at trivially low utilisation.** Evidence: the sizing decision `file:line` + the recorded utilisation measurement (CPU/GPU/mem %) backing the chosen class.
- [ ] **S9.3 — No idle always-on resource: long-lived services that do not need 24/7 availability scale to zero / spin down off-peak, and the scheduling/autoscaling policy that enforces it is in place.** Evidence: the scale-to-zero / schedule / autoscaler config `file:line` + a recorded metric or policy showing the resource is not pinned on at 0 % load.
- [ ] **S9.4 — Data formats and movement are efficient: bulk/analytical data uses a columnar/compressed format (e.g. Parquet/ORC + compression) rather than raw CSV/JSON at scale, and egress/replication is not gratuitous.** Evidence: the storage/serialization config `file:line` naming the format + compression, and the data-movement path `file:line` (or a recorded size/transfer comparison).
- [ ] **S9.5 — Wasteful recomputation is avoided on the hot/batch path: cached/incremental/memoised results replace re-deriving identical expensive outputs, where applicable.** Evidence: the cache/incremental-compute `file:line` + the invalidation/TTL that keeps it correct, OR a cited reason it does not apply.

---

**VETO if:**
1. A cutover is big-bang or unproven — no strangler-fig increments with go/no-go, OR backfill has no reconciliation proof (counts + checksum) (S5.1/S5.4), OR the rollback runbook was written but never drilled (S5.6).
2. An aggregate exposes its state to illegal mutation (public setters bypass invariants) or a single command atomically writes multiple aggregate roots (S6.1/S6.2), OR no anti-corruption layer guards a bounded-context edge and the foreign model leaks inward (S6.4).
3. A published surface ships with no LICENSE / no SPDX, an incompatible inbound license, an untagged public API, OR a semver promise broken with no deprecation window (S8.1/S8.2/S8.3/S8.5).
4. A batch/ML workload runs with no carbon/energy budget or no measured figure against it, OR an always-on resource sits idle/over-provisioned with no scale-down policy (S9.1/S9.3).
